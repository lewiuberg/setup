Master-Data Integration Hub — System Cheatsheet

From 105 Logic Apps to four .NET 10 services on Kubernetes. Source: workbench/proposed-application-design/take-2 + workbench/plans/take-1.

Trigger
Pub/Sub API gRPC CDC AccountChangeEvent Solution__cChangeEvent Platform__cChangeEvent

    Elected by coordination.k8s.io/Lease; warm standby stays idle
  • 2
    Open one Azure SQL DbTransaction
    Wraps the entire handler
  • 3

▶ Outbox relay co-hosted in salesforce-ingest
Poll interval
500 ms BatchSize = 1 ConfirmTimeout = 5 s AlertThreshold = 500
  • 1
    Row-lock next unpublished row
    SELECT TOP (1) … WITH (UPDLOCK, READPAST, ROWLOCK) WHERE publishedToBroker IS NULL ORDER BY id
  • 2
    Publish to masterdata.events topic exchange
    Routing key <aggregate>.<changeType> e.g. customer.updated; MessageId = outboxRow.id
  • 3
    WaitForConfirmsOrDie(ConfirmTimeout)
    RabbitMQ publisher confirms (ConfirmSelect()) before we stamp
  • 4
    Stamp publishedToBroker = SYSUTCDATETIME()
    Short standalone tx; Invariant 2: no stamp before basic.ack
  • 5
    Release row-lock & loop
    /healthz/ready flips unhealthy if channel closed > UnhealthyAfter = 60 s
The UPDLOCK, READPAST window + BatchSize = 1 is what prevents double-publish during rolling deploy.
▶ Dispatch flow consumer-dispatch worker
Per-message pipeline
  • 1
    Receive from bound queue
    e.g. masterdata.consumer.sms.customer
  • 2
    Idempotency check on ConsumerDeliveryLog
    If (consumer, aggregateType, aggregateId, lastOutboxId) already dispatched → ACK + skip
  • 3
    Evaluate Unleash flag for this consumer
    If off → ACK + continue; no downstream call
  • 4
    Apply per-consumer routing
    AI: PlatformId; Analytics: PlatformIds=[8,9]; NumberAdmin: PlatformNames=["PCC","SI"]
  • 5
    Mapperly → frozen DTO (with AfterMap quirks)
    SMS flattened billing, SolAdmin customerKey = Solution.producerExternalId, PCC trim padding …
  • 6
    Typed HttpClient + Polly v8
    Retry(3, 1–8 s, jitter) → CircuitBreaker(50% / 1 min, break 30 s) → Timeout(30 s)
  • 7
    On 2xx: write ConsumerDeliveryLog & ACK
    First-winner also mirrors id to Solution.consumerSolutionId during migration window
  • 8
    On failure past maxRetry = 5: NACK & DLX
    DLX consumer writes RetryDeadLetter; operator replays via admin-api
Special workers
  • A
    PccToSolutionAdminBridgeWorker
    PCC-origin solution events → SolAdmin via 10 s Channel; replaces the pcc-solution-create-solutionadmin-customer 10 s bridge LA
  • B
    PtSolutionWorker (dual target)
    platformArea == OPO → pt-opo; UK1 → pt-uk1; unknown → DLQ with alert (R5)
  • C
    SalesforceSolutionWriteBackHandler
    First-successful solution provisioner calls ISalesforceSolutionWriter.WriteExternalIdAsync to patch Solution__c.Solution_External_Id__c
  • D
    Startup platform-id health check
    Every configured platformId must resolve to a Platform.producerExternalId; otherwise pod refuses Ready (R2)
Every worker is always DI-registered. Feature-flag gating lives inside the loop — flipping a flag re-activates a disabled Logic App in ≤ 30 s with no redeploy.

Two invariants shown explicitly: the ingest commit happens before the checkpoint advances, and the publishedToBroker stamp happens after RabbitMQ confirms. Either pod can crash anywhere and no event is lost or duplicated.
▶ Tech stack cloud-agnostic outside Azure SQL
Layer Choice Why
Runtime .NET 10 Generic Host + BackgroundService Hard constraint: .NET 10 only. No Azure Functions.
Ingestion Salesforce Pub/Sub API (gRPC) + CDC events Tier 1 is REST SystemModstamp polling; Tier 2 is CDC subscriber. PushTopic / Streaming rejected (CometD legacy).
Database Azure SQL (unchanged) System of record. Additive schema only — five new tables, no drops until Phase 6.
Data access Dapper + embedded .sql scripts Per .cursor/rules/database.mdc. Schema ownership in files, not magic strings.
SQL resilience ReliableSqlDbConnection + Polly Retries on Azure SQL transient set 4060 / 40197 / 40501 / 40613 / 49918 / 49919 / 49920 / 11001.
Messaging RabbitMQ topic exchange + per-consumer queues + DLX Transactional outbox is the source of truth; RabbitMQ is the transport. NATS JetStream is the future-fallback.
Autoscaling KEDA RabbitMQ scaler → HPA (2 → 12) Queue depth drives scale-out for consumer-dispatch.
Leader election coordination.k8s.io/Lease via KubernetesClient.Lease Single subscriber + single scheduler invariant; 30 s TTL, 10 s renewal.
HTTP resilience Polly v8 pipelines + IHttpClientFactory Retry(3, 1–8 s jitter) → CircuitBreaker(50% / 1 min, 30 s break) → Timeout(30 s).
Object mapping Mapperly partial mappers Per .cursor/rules/csharp.mdc §11; per-consumer AfterMap hooks for the SMS / SolAdmin / PCC quirks.
Feature flags OpenFeature SDK + Unleash provider (flagd pattern) Disabled-LA reactivation without redeploy; R1 cutover gate; ~15 s toggle latency.
Scheduling In-process PeriodicTimer / NCrontab + TimeProvider Weekly Mon 03:00–03:30 UTC stagger, daily 04:00, 5 min cascade. Unit-testable with FakeTimeProvider.
Observability OpenTelemetry SDK → Collector → Grafana / Loki / Tempo / Mimir Per .cursor/rules/observability.mdc. Metrics gate SLOs and HPA.
Secrets & config ConfigMap + Secret Store CSI Driver IOptions<T> everywhere; vault backend swaps without code change.
Ingress NGINX Ingress Controller + cert-manager (mTLS) Only admin-api has a surface; no external traffic.
Packaging OCI images (aspnet:10.0-alpine) + Helm charts One chart per service, per-env values. Azure DevOps builds and deploys.
Explicit non-choices: no Azure Service Bus, no Azure Functions, no Logic Apps, no Azure App Configuration, no API Management. App Insights OTLP exporter is optional — not load-bearing.

▶ Top migration risks R1–R5
  • R1 — HIGH
    Double-firing during cutover. If both a Logic App and its worker run simultaneously, downstream sees two PUTs / DELETEs (creates have a partial guard; updates / deletes don't). Mitigation: per-consumer Unleash flag flipped only after the LA is disabled; single-writer Lease; contract tests green first.
  • R2 — HIGH
    Platform.id IDENTITY drift + three routing styles. IDENTITY values differ by env; Analytics hardcodes IN (8,9), NumberAdmin uses P.[name]. Mitigation: resolve Platform.id by Salesforce Id at startup; pod refuses Ready if resolution fails; routing values live in ConfigMap.
  • R3 — MED-HIGH
    Tribess transport unknown. No connector-masterdata-tribess.json in the repo. Mitigation: capture wire-snapshots from production LA runs in Phase 0 (mandatory); migrate Tribess last in Phase 3.
  • R4 — HIGH
    Single-slot consumerSolutionId during migration. 11 consumers historically share one column. Mitigation: ConsumerDeliveryLog is the new truth; first-winner mirrors to the old column until Phase 6; retire mirror when no external reader depends on it.
  • R5 — MED
    PT dual connector fan-out. pt-opo and pt-uk1 must both fire keyed on Solution.platformArea. Mitigation: PtSolutionWorker is a dual-target dispatcher; unknown area → DLQ with alert; two-week shadow run before cutover (vs. one week for others).
▶ Phased cutover Phase 0 → 6
  • 0
    Capture wire-snapshots from prod Logic Apps
    Agree DBA reload runbook (Q6); confirm Platform.id IDENTITY stability (Q3); capture Tribess transport (Q1)
  • 1
    DBA applies additive DDL; cluster infra baseline up
    RabbitMQ topology, Unleash flags (all false), OTel collector, KEDA
  • 2
    Deploy salesforce-ingest; Logic App producers stay enabled
    Pub/Sub subscriber writes to outbox; outbox-relay publishes; Account_CompareAndResolve.sql is now the compare path. Exit criterion: lag metric green 72 h.
  • 3
    Deploy consumer-dispatch; cut over consumer-by-consumer
    For each: (a) wire-snapshot test green, (b) disable LA in Azure portal, (c) flip flag. Tribess last. PT shadows two weeks.
  • 4
    Deploy reconciliation; disable *-sync LAs
    Weekly syncs, daily IdP push, UK1 cascade all move to workers. Staging / soft-delete SPs become dormant.
  • 5
    Disable producer Logic Apps
    Pub/Sub has been primary since Phase 2; flip legacy-producer Unleash flags selectively if product requires
  • 6
    DBA drops legacy SPs; retire consumerSolutionId mirror
    CompareAccountObject, InsertSalesforceAccountsFromJson, SoftDeleteCustomerPartner gone. Mirror retired once Q4 ("first successful consumer wins" semantic) is confirmed.
Non-negotiable: at no point may a Logic App and its replacement worker be enabled simultaneously (R1). Flag flip is the last step per consumer, not the first.
